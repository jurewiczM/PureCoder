3 · Run list → transcript

Rail, then a run list, then the actual transcript of the selected run. The verdict is a dot; the evidence is the page.

My pick: 3, and it's a project argument rather than a taste one. Your CLAUDE.md says it twice — "a classifier over the transcripts is not a substitute for reading them", and ok=False attempts=4 reads identically whether the model wrote bad code or the harness refused good code. A dashboard of counters is precisely the thing that hid nine defects until someone opened a log. If the UI puts a stat tile first, it is built around the number this project has already learned not to trust; if it puts the transcript first, the layout carries the discipline.

3 is more work than "a little" — the run list needs state the mock doesn't have. If you want the smaller move now, take 2: it's a strict subset, and 3 stays reachable later without a rewrite.
